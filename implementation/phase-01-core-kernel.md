# Phase 1: Core kernel, database layer, installer, CLI, jobs

**Goal:** a tiny, fast PHP foundation that boots in milliseconds, installs from a zip on shared hosting, and gives every later phase routing, middleware, configuration, database access, migrations, caching, logging, background jobs and a CLI.
**Depends on:** Phase 0 decisions. **Out of scope:** users and login (Phase 2), content (Phase 3).

## 1.1 Directory layout inside `core/src/`
```
Kernel/        Application.php, Container.php, ServiceProvider.php, Config.php, Environment.php
Http/          Request helpers, Response factory, JsonResponse, ProblemDetails, Middleware/*, Kernel.php (pipeline)
Routing/       Router.php (FastRoute wrapper), RouteCollection.php, route cache
Database/      Connection.php, QueryBuilder.php, Expression.php, Transaction helpers, Migrator.php, Migration.php, SchemaInspector.php
Cache/         CacheInterface.php, FileCache.php, ApcuCache.php, PhpArrayCache.php (opcache-friendly compiled files)
Log/           FileLogger.php (PSR-3), Redactor.php
Jobs/          Job.php (interface), JobQueue.php, Worker.php, Scheduler.php, Lock.php
Security/      Crypto.php (libsodium secretbox), Random.php, Ulid.php, HttpClient.php (SSRF-safe), RateLimiter.php
Settings/      SettingsRepository.php
Install/       Requirements.php, InstallerController.php, InstallState.php
Cli/           Console.php, Commands/*
Support/       Clock.php, Str.php, Arr.php, Json.php
```

## 1.2 Request lifecycle (front controller `public/index.php`)
1. Define start time; require `vendor/autoload.php` (classmap authoritative).
2. If not installed (`storage/installed.lock` missing) route everything except static admin assets to the installer.
3. Build the container lazily: services are factories, created on first use. Load config from compiled cache `storage/cache/config.php` (falls back to building it). Config sources, in order: `config/*.php` defaults, `storage/config.php` (written by installer, contains DB credentials, app URL, table prefix), environment variables `BS_*` (override).
4. Route-specific middleware pipeline (PSR-15 style, ordered): `ErrorHandler` -> `RequestId` -> `SecurityHeaders` -> `HttpsEnforcer` -> `MaintenanceMode` -> `BodyLimit` (default 2 MB JSON, uploads handled separately) -> `JsonBody` -> `RateLimit` -> (Phase 2: `Session`, `Csrf`, `Authenticate`) -> route handler.
5. Route groups (compiled into `storage/cache/routes.php`):
   - `/api/v1/*` JSON API (Phases 2-4 add routes)
   - `/install/*` installer (only before install)
   - `/health` liveness (returns `{"status":"ok"}` only; no versions or paths)
   - `/admin/*` static SPA files (served by the web server; PHP fallback serves `admin/index.html` for client routes)
   - `/mcp`, `/oauth/*`, `/.well-known/*` reserved for Phase 8
6. After sending the response, if `fastcgi_finish_request()` exists and the lazy job runner is enabled, run due jobs for at most 5 s (see 1.6).

Performance rules: no reflection-based autowiring at runtime (factories are explicit closures); no file scanning per request; compiled config/routes/schema caches are plain PHP arrays returned from files so OPcache keeps them in memory; measure included-file count in a test (budget < 60 for `/health`).

## 1.3 Database layer
- `Connection`: PDO with `ERRMODE_EXCEPTION`, `EMULATE_PREPARES=false`, `utf8mb4`, `SET time_zone = '+00:00'`, `sql_mode` including `STRICT_TRANS_TABLES,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO`. Detects MySQL vs MariaDB and version; refuses MySQL < 8.0 and MariaDB < 10.6.
- Table prefix applied centrally (`$db->table('users')` -> `` `bs_users` ``).
- `QueryBuilder`: select/insert/update/delete/upsert, where groups, `whereIn`, joins, order, limit, cursor helpers, JSON extract expressions **only from registry-provided paths**, `forUpdate()`, chunked iteration. All values bound. Identifiers validated against `^[a-z_][a-z0-9_]*$` and quoted.
- Transactions with nested savepoints; deadlock retry (max 3) for write operations.
- Query logging in debug mode with timings; slow-query warning in logs (> 200 ms).
- `Migrator`: namespaced (`core`, `plugin:<handle>`), ordered by filename `YYYYMMDDHHMM_description.php`; each migration class has `up()` and `down()`; runs each migration in a transaction where DDL allows; records in `migrations`; `--dry-run` prints SQL; uses `GET_LOCK('bs_migrate', 10)` to prevent concurrent runs.

**Migrations in this phase** (DDL exactly as `docs/01-data-model.md` section 7): `migrations`, `settings`, `jobs`, `rate_limits`.

## 1.4 Configuration, secrets and environment
- `storage/keys/app.key`: 32 random bytes (base64) generated by the installer; `Crypto` wraps `sodium_crypto_secretbox` with a key id prefix to allow rotation (`bs key:rotate` re-encrypts secret settings).
- `SettingsRepository`: typed get/set on `settings` table, encrypts `is_secret` values, caches non-secret settings per request and in APCu if available; change events invalidate cache.
- `APP_DEBUG` false by default; debug only allowed when `environment != production`.
- Environment setting (`production` | `staging`) lives in site settings (Phase 3 singleton) but a bootstrap copy is kept in `storage/config.php` for early middleware.

## 1.5 Cache, logging, rate limiting, HTTP client
- `CacheInterface` with `get/set/delete/remember/clearPrefix`; drivers: `ApcuCache` (if `apcu` loaded and CLI-safe), `FileCache` (atomic write via temp file + rename, sharded directories, TTL in header), `PhpArrayCache` for compiled config/routes/schema.
- `FileLogger`: daily files in `storage/logs`, levels, JSON lines, request id, automatic redaction of keys matching `password|secret|token|authorization|cookie|key`. Retention 14 days.
- `RateLimiter`: fixed-window + burst, buckets from Phase 2/8 use it; storage APCu or `rate_limits` table; returns remaining/reset for headers (`RateLimit-*`), and `429` + `Retry-After`.
- `HttpClient`: cURL wrapper implementing the SSRF rules in `README.md` section 8; used by every outbound call.

## 1.6 Jobs and scheduler (no daemons)
- `JobQueue::push(type, payload, delay, queue, priority)`; `Worker` reserves jobs with `UPDATE ... SET status='running', reserved_at=NOW() WHERE id=? AND status='queued'` (optimistic) and runs handler classes registered by type.
- Each run has a time budget (CLI: default 50 s for a 1-minute cron; lazy runner: 5 s) and a memory guard (stop at 80% of `memory_limit`). Failed jobs retry with exponential backoff; stuck `running` jobs older than 10 min are released.
- Triggers: (a) **cron** `* * * * * php /path/core/bin/bs jobs:run` (recommended; installer shows the exact line), (b) **lazy runner** after responses via `fastcgi_finish_request()`, (c) the admin app pings `POST /api/v1/system/tick` every 60 s while open (Phase 5) as a last resort. The dashboard warns if no job ran for 15 minutes.
- `Scheduler`: code-defined recurring tasks (`prune`, `publish_scheduled`, `integrity_check`, later `deploy_debounce`) with last-run timestamps in `settings`; executed by the worker.

## 1.7 Installer (web, no SSH)
Steps, each a page in a minimal server-rendered installer (plain HTML + CSS, no JS framework; CSRF-protected form posts):
1. **Requirements:** PHP version, required/recommended extensions, `memory_limit`, upload limits, writable `storage/`, HTTPS detected, OPcache on/off; red/amber/green list with fix hints.
2. **Private paths check:** HTTP self-request to `/storage/.probe`, `/config/app.php`, `/vendor/autoload.php`, `/.env`; all must be 403/404 or install stops with instructions (Mode A vs Mode B from README section 4).
3. **Database:** host, port, name, user, password, table prefix (default `bs_`); test connection and version; check privileges (CREATE, ALTER, INDEX, DROP on the prefix).
4. **Site:** site URL (admin/API base), public site URL, environment (production/staging), timezone.
5. **Install:** write `storage/config.php` (0600 where possible), generate app key, run core migrations, seed settings, write `installed.lock`, compile caches.
6. **Owner account:** added in Phase 2 (until then the installer ends after step 5).
7. **Finish:** show cron line, link to admin, reminder to delete nothing (installer self-disables).
After install all `/install` routes return 404. Re-running requires deleting `installed.lock` via file manager (documented recovery).

## 1.8 CLI (`php bin/bs <command>`)
`install` (non-interactive with flags, for hosts with SSH and CI), `migrate`, `migrate:status`, `migrate:rollback --step=1`, `jobs:run [--max-time] [--queue]`, `jobs:failed`, `jobs:retry <id>`, `cache:clear`, `cache:warm`, `key:generate`, `key:rotate`, `health`, `config:show` (redacted). Exit codes non-zero on failure. All commands work on hosts where only the cron shell is available.

## 1.9 Errors and responses
- All API errors are RFC 9457 problem details: `type`, `title`, `status`, `detail`, `instance` (request id), and `errors` (field -> messages) for validation.
- 404/405 for routes, 413 for oversized bodies, 415 for wrong content type, 429 rate limited, 503 maintenance.
- Uncaught exceptions logged with request id; response hides internals unless debug.

## 1.10 `.htaccess` for `public/` (Apache/LiteSpeed) and nginx sample
- Front-controller rewrite for non-existing files; deny dotfiles; deny `*.php` except `index.php`; disable directory listing; long cache headers for `/admin/assets/*` (hashed files) and `no-cache` for `/admin/index.html`; gzip/brotli where available; `public/media/.htaccess` disables script execution (`php_flag engine off`, `RemoveHandler`, `Options -ExecCGI`) and forces safe content types.
- Provide `docs/nginx.conf.example` with equivalent rules.

## 1.11 Tests
- Unit: config merge, container factories, router, query builder (SQL + bindings snapshots, identifier rejection), crypto round-trip and tamper detection, ULID monotonicity, rate limiter, SSRF guard (private IP, DNS rebinding via redirect, IPv6 loopback), file cache atomicity.
- Integration (real DB in CI matrix): migrations up/down/up, settings encryption, job reservation under concurrency (two workers), scheduler.
- HTTP: `/health`, problem-details format, security headers present, body limit, maintenance mode, installer step validation and lock.
- Budget tests: included files for `/health` < 60; memory < 8 MB; p95 boot time measured.

## 1.12 Acceptance checklist
- [ ] Fresh zip installs on both shared-host accounts through the browser installer in under 5 minutes, in Mode A and Mode B.
- [ ] Private paths verified unreachable on both hosts.
- [ ] `/health` responds with all security headers and `X-Robots-Tag: noindex, nofollow`.
- [ ] Migrations run, roll back and re-run cleanly on MySQL 8.0/8.4 and MariaDB 10.6/10.11/11.4.
- [ ] Jobs run from cron and from the lazy runner; a failing job retries and ends in `failed` with the error stored.
- [ ] Rate limiter returns 429 with headers.
- [ ] Logs redact secrets (test with a password in a payload).
- [ ] Budgets recorded in `NOTES.md`.
