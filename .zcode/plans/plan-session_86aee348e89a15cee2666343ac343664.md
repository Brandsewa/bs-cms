# WordPress-style PHP site renderer (publish = instantly live, no Node)

## Goal
Pages render on the fly in PHP from the database, cached as static HTML — exactly how WordPress works. The user just publishes; the site updates immediately. No Node, no build step, near-zero hosting resources (repeat visits serve a cached file).

## Architecture

**New core namespace `core/src/Site/`:**
1. **`SiteRendererController`** — resolves URL path → published entry and renders HTML:
   - `/` → page slug `home` (html_code > Puck content > fallback hero)
   - `/{slug}/` → `pages` collection; `/blog/` archive + `/blog/{slug}/` → `posts`; `/{collection}/...` → custom collections (uses CollectionRegistry; URL patterns from PublishingSettingsRepository)
   - Redirects table checked on miss; styled 404 page on true miss
2. **`PuckRenderer`** — PHP port of the 9 page-builder components (Hero, RichText, Callout, Faq, CtaBanner, FeaturesGrid, ImageBlock, Spacer, ContactForm placeholder) emitting the exact same `.bs-*` classes; per-entry `html_code` wins precedence (starter convention)
3. **`TiptapRenderer`** — PHP port of `@bs/renderer` `renderToHtml` for post bodies (paragraph/headings/lists/quotes/images/callouts/etc., URL sanitization, `bs://` resolution)
4. **`PageLayout`** — PHP BaseLayout: head/meta/canonical/OG, branding CSS-var style (port of `brand.ts`), nav + footer from `/api/v1/public/site` data source (singleton queries, no HTTP call), 404 page
5. **`SitemapRenderer` / `RssRenderer`** — dynamic `/sitemap.xml` and `/rss.xml` (no more stale static files)
6. **`RenderedPageCache`** (in `Content/Cache/`, modeled on `PublicResponseCache`) — rendered HTML cached per URL path under `storage/cache/site/`; **full-flush on the existing publish events** (`entry.*`, `navigation.*`, `settings.*`, `branding.*`) inside the `subscribeAll` closure in CoreServiceProvider where `$changedUrls` is already computed

**Routing (both front-controller variants):** site routes registered LAST after ApiRoutes — specific routes (`/sitemap.xml`, `/rss.xml`) then catch-all `GET /{slug:.+}`; `/api`, `/admin`, `/oauth`, `/mcp`, `/health` all match earlier so they're unaffected. Existing static files (media, admin assets) still win before routing.

**Static assets:** copy `tokens.css` + page-builder `styles.css` + `embed.js` into `core/public/site-assets/` (served as plain files; contact forms keep hydrating against the existing public forms API).

**Out of scope (v1):** Pagefind search index and markdown twins / llms.txt (stale leftovers removed from live docroot); draft preview stays on the existing preview mechanism; Astro starter remains available for users who want the fancy pipeline (static files still win over renderer if present).
